## Executive Summary

`wayfinder-ui` was modeled directly after `grill-with-ui`, adopting its split-ownership Inter-Process Communication (IPC) architecture, zero-dependency Node.js daemon, atomic JSON patching engine, and dual runtime listening modes (persistent Monitor vs. foreground blocking Wait loop). 

However, `wayfinder-ui` transforms the domain model from a linear series of questioning rounds (`topic -> rounds -> questions`) into an architectural decision Directed Acyclic Graph (`destination -> map -> ticket DAG + fog of war`).

This investigation provides:
1. A rigorous audit of **exactly where and how all session data is stored** across disk, environment variables, in-memory structures, browser storage, logs, and external tracking systems.
2. A comprehensive **functional parity matrix and gap analysis** comparing `wayfinder-ui` against `grill-with-ui`, identifying where `wayfinder-ui` deliberately innovated, where it successfully achieved parity, and where critical regressions, incomplete UI implementations, and test coverage gaps exist.

## 1. Complete Session Data Storage Architecture

Every byte of session data in `wayfinder-ui` has an explicit lifecycle and storage boundary designed to prevent git repository pollution while supporting crash-resilient session resumption.

```
~/.wayfinder-ui/sessions/<project-key>/<timestamp>/
├── state.json          # Agent-owned state document (atomic patch writes only)
├── events.jsonl        # Client-owned append log (server POST /send handler)
├── server.json         # Daemon metadata: { url, port, pid, started }
├── visual.html         # Optional subagent-generated SVG/HTML architecture visual
├── research/           # Optional subagent outputs: <ticket-id>.md
└── serve.log           # Stdout/stderr when started detached in wait mode
```

## 3. Deep-Dive Analysis of Key Architectural Differences

### 3.1 The DAG & Cycle-Detection Engine (Wayfinder Innovation)
In `grill-with-ui`, questions move strictly forward across linear "rounds" ([`repositories/grill-with-ui/SKILL.md:206-225`](file:///home/mezmo/Work/vibe/agent-skills/repositories/grill-with-ui/SKILL.md#L206-L225)). A question's `deps` array is informational and used only to render breadcrumb links ([`repositories/grill-with-ui/page.html:497`](file:///home/mezmo/Work/vibe/agent-skills/repositories/grill-with-ui/page.html#L497)).

In contrast, `wayfinder-ui` implements a true topological graph engine directly in `server.mjs`:
1. **Bidirectional Edge Maintenance:**
   When ticket $T$ declares `blocked_by: [B1, B2]`, `patchTickets` automatically finds tickets $B_1$ and $B_2$ and mutates their `blocks` arrays to include $T$ ([`repositories/wayfinder-ui/server.mjs:448-459`](file:///home/mezmo/Work/vibe/agent-skills/repositories/wayfinder-ui/server.mjs#L448-L459)).
2. **Cycle Prevention:**
   `validateDAG()` constructs an adjacency list and runs a depth-first search tracking the current recursion stack (`recStack`). If any back-edge is encountered, it rejects the patch and leaves `state.json` untouched ([`repositories/wayfinder-ui/server.mjs:521-549`](file:///home/mezmo/Work/vibe/agent-skills/repositories/wayfinder-ui/server.mjs#L521-L549)).
3. **Reactive Frontier Advancement:**
   When an agent resolves ticket $A$ (`status: "resolved"`), `patchTickets` loops through all tickets in `frontier` or `blocked` status. If all IDs in a ticket's `blocked_by` list are resolved, the ticket's status is promoted to `"frontier"` ([`repositories/wayfinder-ui/server.mjs:461-471`](file:///home/mezmo/Work/vibe/agent-skills/repositories/wayfinder-ui/server.mjs#L461-L471)). This completely eliminates manual status bookkeeping for the agent.

### 3.2 Visual & Prototype Subagent Workflow
Both repositories define a background subagent visual workflow (`visual-brief.md`):
- **Contract:** The main agent never writes HTML/SVG directly into its context to conserve tokens. It launches a background subagent with `visual-brief.md` to write `<session>/visual.html` directly ([`repositories/grill-with-ui/SKILL.md:238-242`](file:///home/mezmo/Work/vibe/agent-skills/repositories/grill-with-ui/SKILL.md#L238-L242), [`repositories/wayfinder-ui/SKILL.md:135-140`](file:///home/mezmo/Work/vibe/agent-skills/repositories/wayfinder-ui/SKILL.md#L135-L140)).
- **Parity Status:**
  - `server.mjs` in both repositories serves `/visual` ([`repositories/wayfinder-ui/server.mjs:246-250`](file:///home/mezmo/Work/vibe/agent-skills/repositories/wayfinder-ui/server.mjs#L246-L250)) and validates/merges `visual` in `applyPatch` and `stampTimes` ([`repositories/wayfinder-ui/server.mjs:405-412, 512`](file:///home/mezmo/Work/vibe/agent-skills/repositories/wayfinder-ui/server.mjs#L405-L412)).
  - **However, in `wayfinder-ui/page.html`, there is NO user interface for visuals.** There is no "Visualize" button in the header, no sandboxed `<iframe>` to render `visual.html`, and no visual feedback discussion tray.

### 3.3 Critical Gaps in `wayfinder-ui/page.html`
While `server.mjs` in `wayfinder-ui` is clean, robust, and passes all tests, `page.html` is an early-stage prototype with several regressions relative to `grill-with-ui`:
1. **Volatile Staging:** Staged actions live only in JavaScript memory (`let staged = []`). Closing or reloading the tab loses all staged work.
2. **Missing In-Flight Pending Loop:** In `grill-with-ui`, sends stay in `local.pending` with spinning loaders until the agent's patch arrives with `agent.handled >= seq`. In `wayfinder-ui`, `page.html` immediately clears `staged = []` upon HTTP 200 from `/send`, leaving the user with no visual cue that the agent is currently processing those actions.
3. **No Finish Trigger:** The user cannot click "Finish" in the web UI.
4. **No Fog Graduation Controls:** Fog items are listed as passive text. There is no button to graduate fog into a ticket or stage new fog items.
5. **No Free-Text Decision Answers:** In `grill-with-ui`, the user can type free-text nuance in a textarea to stage a custom answer. `wayfinder-ui/page.html` only permits clicking predefined options or "Accept Recommendation".
6. **No Responsive Design or Accessibility:** Missing CSS media queries for viewports `<760px` and `prefers-reduced-motion`.

## 5. Summary of Key Takeaways & Recommendations

1. **Storage Integrity:**
   `wayfinder-ui` correctly adheres to the zero-repo-pollution storage model (`~/.wayfinder-ui/sessions/<project-key>/<timestamp>/`). All worktrees of a git repository correctly map to the same session store.
2. **Backend Robustness:**
   `server.mjs` in `wayfinder-ui` is high quality. It retains the atomic split-ownership guarantees of `grill-with-ui` while successfully adding DAG edge reconciliation, topological frontier promotion, and cycle detection.
3. **Frontend Needs Modernization:**
   `page.html` in `wayfinder-ui` needs to adopt the battle-tested frontend patterns from `grill-with-ui`:
   - Store staged actions, pending sends, and drafts in `localStorage`.
   - Add the missing `Visualize` view with sandboxed iframe.
   - Add the `Terms` dropdown and `Finish` confirmation flow.
   - Add ticket action controls for free-text answers and graduating fog items.
   - Add responsive breakpoints for narrow viewports.
4. **Test Suite Expansion:**
   Port the comprehensive unit test assertions and Playwright E2E browser tests from `grill-with-ui/test/` to `wayfinder-ui/test/` to safeguard against regressions.
